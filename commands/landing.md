# /lhg-landing-page:landing —— 一句话变高转化落地页

用户输入在 `$ARGUMENTS` 中：`"<产品一句话描述>"`。

> **边界声明（先讲清）**：本命令只做**营销落地页**（单页、讲清价值、引导行动）。
> 如果需求涉及用户登录、数据库、多页面复杂交互、支付对接等"完整应用"，
> 明确告诉用户这超出了落地页的范围，建议改用 `lhg-fullstack` 插件。

## 执行流程

### Phase 1：卖点提炼（加载 lhg-lp-strategy）
1. 加载 skill `lhg-lp-strategy`，按"≤5 个苏格拉底问题"澄清：受众是谁、解决什么痛点、和竞品比有什么不一样、有没有真实证据（数据/评价/案例）。
2. 用你所在平台的提问能力逐个问（一次 1-2 个），先开放后收敛。
3. 输出卖点卡片：一句话价值主张 + 核心卖点×1 + 支撑卖点×3 + 信任证据清单。**没有真实证据就写"待补充"，不许编。**

### Phase 2：线框结构（加载 lhg-lp-design）
1. 按 `lhg-lp-design` 第 2 节的标准区块画 ASCII 线框：顶栏 / 首屏 / 信任条 / 功能 / 社会证明 / 定价 / FAQ / 最终 CTA / 页脚。
2. 每个区块写一句话内容说明（不是文案正文，是"这里放什么"）。
3. 线框给用户过一眼，确认后再写代码。**线框未确认不开工。**

### Phase 3：高保真实现（加载 lhg-lp-build）
1. 按 `lhg-lp-build` 六步流程实现：设计令牌 → 静态骨架 → 填真实文案 → 交互 → 动效 → 自查。
2. 技术选型默认：纯静态 HTML + Tailwind（CDN 或构建版均可），单文件可部署；
   用户明确要框架时再上 Next.js 等。
3. 文案红线：数字/评价/客户 logo 没有真实来源就不写，用诚实占位。

### Phase 4：转化检测（加载 lhg-lp-audit）
1. 运行审计脚本：
   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/landing_audit.py --target <页面目录> --format text
   ```
2. blocker 必须清零（修或列入"需人工处理"）；warning 修掉或写豁免理由。
3. 按 `lhg-lp-audit` 第 5 节做人工评审：首屏 3 秒测试、移动端实测、表单走一遍。
4. 结论只能是"通过"或"不通过"。

### Phase 5：交付 + 部署指引
给用户一份交付报告：
- 做了什么（页面结构 + 本地预览方式）
- 自查结论（blocker/warning/nit 数量与处理情况）
- 需人工处理项（真实文案、真实图片、域名、统计代码）
- 部署指引：见 `/lhg-landing-page:ship`

## 硬规则
- 卖点没提炼就画线框 → 停下来先提炼。
- 线框没确认就写代码 → 先确认线框。
- blocker 没清零就说"做完了" → 不许。
- 页面文案编造数字/评价 → 改成诚实占位。
- 用户要的是完整应用 → 明确引导到 lhg-fullstack，不硬做。
