# /lhg-landing-page:ship —— 落地页部署

用户输入在 `$ARGUMENTS` 中：`[页面目录]`。目录缺省为当前项目根目录。

## 流程

### 1. 上线前门禁
先跑一遍 `/lhg-landing-page:audit`，blocker 必须清零，否则不许进入部署。

### 2. 托管选型（按场景推荐，不替用户做决定）
| 场景 | 推荐 | 说明 |
|---|---|---|
| 纯静态单文件/多文件 | Cloudflare Pages | 免费、快、国内访问稳，拖文件夹即部署 |
| 已在用 Vercel 生态 | Vercel | 与 Next.js 项目无缝衔接 |
| 极简（一个 HTML 文件） | GitHub Pages / Netlify Drop | 5 分钟上线，适合验证期 |
| 需要表单收数据但无后端 | 表单即服务（Formspree / 飞书多维表格 API） | 别为收个表单搭服务器 |

选型只给建议，最终由用户拍板。**账号登录、域名购买、DNS 解析等操作由用户亲手完成**，只给一步一步的指引。

### 3. 上线 checklist（逐项打勾）
- [ ] `audit` blocker 清零
- [ ] 真实文案/图片已替换所有占位
- [ ] 表单提交链路实测通过（收到测试数据）
- [ ] 统计代码已加（至少一个：GA / 51.la / Cloudflare Web Analytics）
- [ ] title / description / OG 标签已填
- [ ] 移动端真机（或等宽视口）看过首屏
- [ ] favicon 已加（没有就用 emoji SVG 顶一下）
- [ ] 404/异常页不阻断（单页可跳过）

### 4. 发布后复测
上线 24 小时内回看：统计有数据进来吗、表单收到测试提交了吗、
手机打开首屏 3 秒内能看全吗。有问题记入待办，不算"做完了"。

## 硬规则
- audit 没过就部署 → 不许。
- 让用户买的域名/开的账号 → 只给指引，不代操作。
- 上线不加统计 → 等于闭眼开车，必须加。
